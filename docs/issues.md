# Issue Management

作業中に気づいたバグ・技術的負債・改善点は、指示を待たずに `.issues/` に起票すること。

## ディレクトリ構成
.issues/
open/    # 未対応の issue
closed/  # 対応済みの issue

## ファイル命名規則
{YYYYMMDD}-{title}.md
title は kebab-case または日本語で、理解のしやすい短い文章を用いる。
記号などは適切にサニタイズすること。
例: 20260531-認証情報の修正.md

## ファイルフォーマット

```markdown
# {タイトル}

## 概要

## 背景

## 実装/修正プラン

## ログ

### {YYYY-MM-DD HH:MM:SS} {エージェント名} {モデル名}

起票した: {起票理由}

```

ログは時系列で末尾に追記していく。
どのような内容を含めても良いが、以下に示すものがある場合は必ず追記する。

- どのような変更が行われたか
- なぜその変更が行われたか
- 重要な実装上の詳細
- 今回あえて対応しなかった内容

## 操作ルール

- **起票**: `open/` にファイルを作成する
- **コメント**: 該当ファイルの `## ログ` に追記する
- **クローズ**: `open/` から `closed/` にファイルを移動する
- 1つの issue につき1ファイル
- 既存 issue に関連する作業をしたときはログに追記する
    - このとき、過去のログは編集せず、必ず追記で行うこと
- 添付ファイルや、関連する複雑な情報などを保持したい際は、ファイル名と同名のディレクトリを作成し、その中に入れること
